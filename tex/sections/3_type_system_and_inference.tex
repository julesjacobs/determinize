\section{Type System and Inference}
\label{sec:type-system}

\subsection{Typing}

Whether replacing a sample by its mean is valid depends on how the
sampled value is subsequently used.
We therefore introduce a type system that checks whether sampled values are used in ways that justify replacing them by their means. \Cref{fig:typing} presents the typing rules.
The judgment $\Gamma\vdash e:\tau$ assigns expression $e$ type
$\tau$ under context $\Gamma$. Alongside standard types for
functions, pairs, sums, and lists, real types carry an annotation
$m\in\{\G,\E\}$:
\begin{itemize}
    \item $\tyR\G$ describes real values that determinization leaves
    unchanged.
    \item $\tyR\E$ describes real values that may change under
    determinization and whose uses are restricted to affine operations.
\end{itemize}
The subtyping relation
$\tyR\G<:\tyR\E$ allows values of type $\tyR\G$ wherever values of type $\tyR\E$ are permitted, but not conversely.
Subtyping extends to compound types as well.

\input{figures/typing}

\paragraph{Typing rules.}
The key principle is that operations must preserve expectations when values of type $\tyR\E$
are replaced by their means. The rules enforce this as follows:

\begin{itemize}
    \item \textbf{Addition and negation.}
    Both permit operands of type $\tyR\E$ because expectation is
    linear, even for dependent random variables.

    \item \textbf{Multiplication and division.}
    Multiplication requires a left operand of type $\tyR\G$,
    while division requires a denominator of type $\tyR\G$.
    Determinization preserves these values, and scaling by such a value is linear in the other operand (assuming
    a nonzero denominator).
    For example, let $x=\kw{uniform}^{\G}(0,1)$ and $y=\kw{gaussian}^{\E}(x,1)$. For each sampled value of $x$, $y$ has mean $x$, so $x*y$ has mean $x^2$. Determinization leaves $x$ unchanged and replaces $y$ by $x$, giving exactly $x^2$. A limitation of this rule is that it rejects multiplication of two $\E$ values even when they are independent; supporting this case would require an additional analysis to establish independence between random variables.

    \item \textbf{Comparisons.}
    Both operands must have type $\tyR\G$, ensuring that
    determinization does not change their outcomes
    and consequently alter control flow.

    \item \textbf{Distribution parameters.}
    Parameters may have type $\tyR\E$ when the distribution's
    mean depends affinely on them. For example,
    $\kw{uniform}^{\E}(0,y)$ permits an upper bound
    of type $\tyR\E$ because its mean is $y/2$.
    Similarly, Gaussian means, Poisson rates, Bernoulli
    probabilities, discrete probabilities, and gamma
    shapes may have type $\tyR\E$. In contrast, exponential
    rates, beta parameters, Gaussian variances, and
    gamma rates must have type $\tyR\G$, since the
    corresponding mean is not affine in those
    parameters or does not depend on them.
\end{itemize}

Finally, the distribution rules impose $\alpha\in\{m,\M\}$:
$\G$-mode sampling produces values of type $\tyR\G$,
$\E$-mode sampling produces values of type $\tyR\E$,
and $\M$-mode mean evaluation may produce either.
In particular, $\G$-mode distributions require
parameters of type $\tyR\G$, preserving their sampling
behavior under determinization.

\subsection{Type Inference}
\label{sec:type-inference}

The typing rules in \cref{fig:typing} check whether a given choice of sampling modes is valid. We now describe how to \emph{infer} these modes,
together with the types of expressions. Our goal is to assign mode $\E$
to as many sampling sites as possible, subject to the typing rules.

\subsubsection{Constraint Generation}

\input{figures/inference}

We generate constraints using judgments of the form
$\Gamma\vdash e\Rightarrow\tau\mid C$, meaning that under context
$\Gamma$, expression $e$ has type $\tau$ provided that the set
$C$ of constraints is satisfied.
We use mode variables $a,b,\ldots$, ranging over $\{\G,\E\}$,
to represent unknown annotations on real types, and type variables
$X,Y,\ldots$ to represent unknown types.
In particular, $\tyR a$ denotes a real type whose mode is yet
to be determined. We order annotations by $\G\le\E$, reflecting the
subtyping relation $\tyR\G<:\tyR\E$. Thus,
$\tyR a<:\tyR b$ holds exactly when $a\le b$:
the permitted assignments are $(\G,\G)$, $(\G,\E)$,
and $(\E,\E)$, while $(\E,\G)$ is forbidden.

Each rule recursively infers types for its subexpressions,
introduces fresh variables as needed, and collects the constraints
imposed by the corresponding typing rule.
These constraints capture the restrictions on how values may be used:
for instance, an operation requiring a $\G$-typed operand imposes
constraints on the expression producing that operand.
For each sampling site, a fresh mode variable determines whether
the site can be annotated with $\E$ or must remain $\G$;
an explicit annotation $m\in\{\G,\E\}$ additionally imposes
the constraint $a=m$.
Selected rules appear in \cref{fig:inference}; the complete rules
are given in \cref{sec:appendix-constraint-generation}.



\begin{example}[Constraint generation]
\label{ex:constraint-generation}
Consider the following program, with all sampling sites unannotated:
\[
\begin{aligned}
&\kw{let}\ x=\kw{uniform}(0,1)\ \kw{in}\\
&\kw{let}\ y=\kw{gaussian}(x,1)\ \kw{in}\\
&\kw{let}\ z=\kw{gaussian}(y,1)\ \kw{in}\\
&\kw{if}\ x<1/2\ \kw{then}\ x*z\ \kw{else}\ z+1.
\end{aligned}
\]
Let $a_x,a_y,a_z$ denote the fresh mode variables
associated with the three sampling sites.
By \textsc{Let} and \textsc{Var}, subsequent uses of
$x,y,z$ have types $\tyR{a_x},\tyR{a_y},\tyR{a_z}$,
respectively.
Similarly, applying the remaining rules in
\cref{fig:inference} generates the following
subtype constraints:
\[
\begin{aligned}
\tyR{a_x}<:\tyR{a_y},\quad
\tyR{a_y}<:\tyR{a_z}
  &\quad\text{(\textsc{Gaussian})}\\
\tyR{a_x}<:\tyR\G
  &\quad\text{(\textsc{Cmp}, \textsc{Mul})}\\
\tyR{a_z}<:\tyR{a_t},\quad
\tyR{a_z}<:\tyR{a_f}
  &\quad\text{(\textsc{Mul}, \textsc{Add})}\\
\tyR{a_t}<:X,\quad
\tyR{a_f}<:X
  &\quad\text{(\textsc{If})}.
\end{aligned}
\]
Here $a_f$ is the mode variable of the else branch's
result type, and $X$ is the fresh type variable
introduced by \textsc{If}.
We omit the constraints involving numeric constants
and the trivial Boolean guard constraint; these are
generated by the same rules.
\end{example}

\subsubsection{Constraint Solving}

\input{figures/inference-solving}

We solve the generated constraints following
\citet{traytel2011subtyping}. Constraint solving decomposes subtype constraints into constraints on their $\mathrm G/\mathrm E$ annotations, expanding unknown types as needed. We repeatedly alternate subtype constraint reduction
and type variable resolution, as shown in
\cref{fig:inference-solving}.
Constraints between types with matching constructors are
reduced to constraints on their components, with function
arguments handled contravariantly.
When an unresolved type variable $X$ is constrained against
a type $\tau$ with a known outer constructor, we expand $X$
to $h(\tau)$, which preserves that constructor while
introducing fresh variables for its components.
Each substitution is applied throughout the constraints,
and constraints between unresolved type variables are
deferred until their structures become known.
This process continues until no further reductions or
expansions are possible, leaving mode inequalities
$a\le b$, where $\G\le\E$.

Finally, we solve the mode inequalities by propagating forced
assignments: $a\le b$ forces $b=\E$ if $a=\E$, and forces
$a=\G$ if $b=\G$.
We repeat until no further assignments are forced, rejecting
conflicting assignments.
Any remaining mode variables are assigned $\E$, maximizing
the number of sampling sites that can be determinized, while
remaining unresolved type variables are assigned $\tyU$.



\begin{example}[Constraint solving]
Continuing \cref{ex:constraint-generation}, we apply
\cref{fig:inference-solving} to reduce the generated
subtype constraints. The constraint $\tyR{a_t}<:X$
requires type variable resolution, followed by
subtype constraint reduction:
\[
\tyR{a_t}<:X
\;\rightarrow{X\mapsto\tyR b}\;\;\;
\tyR{a_t}<:\tyR b
\;\leadsto\;
a_t\le b,
\]
where $b$ is fresh. Applying the same substitution
to $\tyR{a_f}<:X$ and reducing gives $a_f\le b$.
The remaining real-type constraints reduce directly
to mode inequalities:
\[
\begin{gathered}
a_x\le a_y,\quad a_y\le a_z,\quad a_x\le\G,\\
a_z\le a_t,\quad a_z\le a_f,\quad
a_t\le b,\quad a_f\le b.
\end{gathered}
\]

Mode constraint solving forces $a_x=\G$,
since $a_x\le\G$. No other mode variables are
forced to $\G$, so all remaining variables are
assigned $\E$.
Thus, inference assigns the sampling sites
\[
(a_x,a_y,a_z)=(\G,\E,\E)
\]
and the program has type $\tyR\E$.
Determinization consequently retains the uniform
sample while replacing both Gaussian samples by
their conditional means.
\end{example}




To state the guarantee, a \emph{completion} of an expression $e$ is
an expression $e'$ obtained by annotating every unannotated sampling
site with $\G$ or $\E$, while preserving existing annotations,
such that $\vdash e':\tau$ for some type $\tau$. For two completions,
write $e'\le e''$ if they differ only at sampling sites annotated
$\G$ in $e'$ and $\E$ in $e''$. Thus, larger completions permit at
least as much determinization.

\begin{theorem}[Inference correctness\leanref{inference}]
\label{thm:inference}
If $e$ has a completion, inference returns a completion $\hat e$ of $e$
and a type $\tau$ with $\vdash\hat e:\tau$, and $e'\le\hat e$ for
every completion $e'$ of $e$. Otherwise, inference fails.
\end{theorem}
