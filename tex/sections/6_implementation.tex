\section{Implementation}
\label{sec:implementation}

The theory from the previous sections is completely formalized and accompanied by a complete pipeline in the Lean programming language \cite{lean} with the formalization relying heavily on previous formalizations in the Mathlib library \cite{mathlib}. The final implementation was mostly carried out by a combination of Claude Fable 5.1 and ChatGPT Astra. The formalization of the main theorems was guided by our pre-existing paper proofs and the implementation of the complete compilation pipeline was based on pre-existing handwritten prototypes. The formalization of the correctness of (parts of) the pipeline is mostly mechanical [TODO: check].

In order to make it clear which parts of the pipeline need human review and which ones can be left to the Lean type-checker, we separated the code into three parts:
\begin{itemize}
\item Trusted surface: This part requires the most scrutiny
\item parts of the pipeline that do not need to be verified directly since they produce a verifiable certificate
\item the the actual proofs: the correctness and relevance of this part is guaranteed by the Lean type-checker
\end{itemize}

\begin{enumerate}
\item \verb+parse+ [TODO: Link]: tokenizes and parses the raw input string into a raw syntax tree that still has strings variables as strings
\item \verb+elaborate+ [TODO: Link]: converts the raw syntax tree into a de-Bruijn-indexed final syntax tree
\item \verb+infer+ [TODO: Link]: infers the types and sampling modes/affinities and creates a certificate
\end{enumerate}

The syntax tree might contain sampling mode/affinity annotations, those will be inferred later
