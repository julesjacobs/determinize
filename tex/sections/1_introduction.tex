\section{Introduction}
\label{sec:introduction}

Probabilistic programming languages (PPLs) extend standard languages with constructs for manipulating random variables~\cite{kozen1981semantics,gordon2014probabilistic,vandeMeent2018introduction,carpenter2017stan,bingham2019pyro,cusumano2019gen}. Many PPLs also support conditionals, higher-order functions, and recursion, which make programs expressive but harder to analyze. A basic question is what a probabilistic program returns on average, that is, the expected value of its output.

Expectations can be computed exactly, using symbolic methods~\cite{gehr2016psi,gehr2020lpsi,moosbrugger2022moment}, or estimated like in Monte Carlo methods, by running the program many times. Hybrid approaches, such as conditional Monte Carlo and Rao--Blackwellization, average over some random choices analytically rather than sampling them to reduce variance~\cite{casella1996rao,owen2013montecarlo}. One can also achieve reduced variance by interleaving symbolic reasoning with sampling during inference~\cite{murray2018delayed,atkinson2022semisymbolic}. 

The core question we address in our paper is motivated by these methods: which random choices can we remove from the program without changing its expected value? One can quickly see that simply replacing a sample by its mean need not preserve this value. The sample may determine a branch, set the parameter of a later distribution, or enter a nonlinear computation, all of which might affect the soundness of the replacement. We will overcome these challenges by using types!  

\begin{wrapfigure}{r}{0.28\linewidth}
\vspace{-1.75em}
\begin{lstlisting}[xleftmargin=0pt]
let x = uniform(0, 1) in
let y = gaussian(x, 1) in
let z = gaussian(y, 1) in
x * z
\end{lstlisting}
\vspace{-2em}
\end{wrapfigure}
To make the challenges more concrete, consider the program on the right, which samples a signal $x$ uniformly
from $[0,1]$, then samples a Gaussian measurement $y$ with mean $x$ and a Gaussian measurement $z$ with mean $y$,
then returns the product $xz$. Once $x$ is fixed, the measurement
noise contributes nothing to the expected output:
$$
  \mathbb E[xz\mid x]
  =x\,\mathbb E[z\mid x]
  =x\,\mathbb E[\mathbb E[z\mid x,y]\mid x]
  =x\,\mathbb E[y\mid x]
  =x^2.
$$
Replacing both Gaussian samples by their means yields a simpler
program that samples only $x$ and returns $x^2$:
\lstinline{let x = uniform(0, 1) in x * x}. Both the source and transformed programs have
expected value $1/3$, but replacing the measurement noise reduces output
variance from $\signalSourceVariance$ to $\signalTargetVariance$, a factor
of $\signalReduction\times$.

This example also exposes the central difficulty in the transformation: had we also replaced the
 uniform sample by its mean, $1/2$, the resulting program would 
return $1/4$ rather than $1/3$ and hence not be equivalent to the source program. Thus, only two random variables can be soundly replaced in this example, and
the third must remain. Whether a sample can be replaced depends on how its value is used: the returned value of the above program is linear in $z$ when $x$ is fixed,
but becomes quadratic in $x$ after averaging over $y$ and $z$. A sound
transformation must therefore reason about both the dependencies
between random choices and their uses throughout the program. This challenge becomes particularly pronounced in higher-order, potentially unbounded recursive programs, where the influence of a random choice can propagate through function calls and across arbitrarily long executions. 

Our key insight is that safe replacements can nevertheless be
identified compositionally from how sampled values are used,
without requiring symbolic marginalization of their distributions.
We introduce \emph{determinization}, a type-directed,
source-to-source transformation of higher-order, recursive
probabilistic programs with continuous distributions that
automatically identifies which samples can be replaced by
their means. 

\begin{wrapfigure}{r}{0.32\linewidth}
\vspace{-1.75em}
\begin{lstlisting}[xleftmargin=0pt]
let x = uniform[G](0, 1) in
let y = gaussian[E](x, 1) in
let z = gaussian[E](y, 1) in
x * z
\end{lstlisting}
\vspace{-2em}
\end{wrapfigure}
Our type system will distinguish sampling choices
that remain random (annotated by $\G$) from those that can be eliminated
($\E$). Revisiting the signal example from earlier would yield the type annotated program on the right. Type inference automatically determines these modes by tracking
how sampled values are used: values marked $\E$ may
participate in affine computations, but cannot determine
control flow or the parameters of retained samples. 

Our transformation then replaces each $\E$-sample by
its mean. We establish soundness of this type-directed transformation through a
relational proof that connects the original and transformed
programs via two interpretations of a common symbolic
semantics. The resulting program
preserves the expected value of the output while never
increasing its variance.

The next three examples illustrate, at a high level, how determinization handles
higher-order functions, data structures, and unbounded recursion.

Consider an example of a Gaussian random walk in
\cref{fig:intro-gaussian-walk} (on the left).
This {\em higher-order} program passes a probabilistic step function to
\texttt{reduce}, a left fold that traverses the requested times
and accumulates {\em a list} of time-position pairs.
At each time $t'$, it samples a new position $y'$ from
$\mathcal N(y,t'-t)$, where $(t,y)$ is the latest pair in the path. It then adds $(t',y')$ to the front of the path. At the next step, it reads that pair and uses $y'$ as the next Gaussian's mean. Our type inference procedure will mark the Gaussian sampling
step as determinizable without unrolling the traversal. 
Replacing the draws by their means keeps every position at zero,
yielding a deterministic path that matches the expected position
at each requested time.

\begin{wrapfigure}{l}{0.39\linewidth}
\vspace{-1.75em}
\begin{lstlisting}[xleftmargin=0em]
let crawl = fun loot =>
  (rec visit d =>
    if flip[G](0.25) then 0
    else loot d + visit (d + 1)
  ) 1
in
crawl (fun d => 200 * d 
              * bernoulli[E](0.01))
\end{lstlisting}
\vspace{-1.75em}
\end{wrapfigure}
\noindent For recursion, consider the dungeon crawl program on the left, which recursively visits
rooms until an exit coin ends the computation, with no fixed
bound on the number of rooms visited.
 At depth $d$, a room pays a jackpot of $200d$ with probability
$0.01$. The type inference will identify that the exit coins remain random because they control
recursion, while each jackpot contributes linearly to the total
reward and can be replaced by its mean payout, $2d$. The determinized program will have the last two lines replaced by \lstinline{crawl (fun depth => 2 * depth)} and one can show that it has the same expected value. Notably, once again this type-directed transformation reduces output
variance (this time by a factor of $12.36$), with the new program needing correspondingly fewer samples to achieve the same estimator variance.

Our determinization procedure can in some cases go beyond improving sampling: it can enable exact expectation computation by transforming an infinite-state program into a finite-state one.

\begin{wrapfigure}{l}{0.32\linewidth}
\vspace{-1.75em}
\begin{lstlisting}[xleftmargin=0pt]
(rec run x =>
  if flip[G](0.5) then x
  else run
   (1 - x + gaussian[E](0, 1))
) 0
\end{lstlisting}
\vspace{-1.75em}
\end{wrapfigure}
Consider, on the left, a recursive process that either returns
its current state $x$ or continues from value $1-x$ plus Gaussian
noise, each choice with probability $1/2$. Type inference labels the two random variables adequately and enables determinization to identify that the gaussian can be replaced by its mean.

\begin{wrapfigure}{r}{0.3\linewidth}
\vspace{-1.75em}
\begin{lstlisting}[xleftmargin=0pt]
(rec run x =>
  if flip[G](0.5) then x
  else run (1 - x)
) 0
\end{lstlisting}
\vspace{-1.75em}
\end{wrapfigure}
 Hence determinization removes the noise, yielding the program on the right: starting from zero, the transformed loop has only two possible states, $0$ and $1$.
Let $v_i$ denote the expected value eventually returned by the
transformed program when entering the loop with $\texttt{x}=i$,
accounting for all subsequent iterations. The expected outputs
from these two states satisfy
\[
 \begin{pmatrix}v_0\\v_1\end{pmatrix}
 =\begin{pmatrix}0&\tfrac12\\\tfrac12&0\end{pmatrix}
  \begin{pmatrix}v_0\\v_1\end{pmatrix}
  +\begin{pmatrix}0\\\tfrac12\end{pmatrix}
 \qquad\Longrightarrow\qquad
 \begin{pmatrix}v_0\\v_1\end{pmatrix}
 =\begin{pmatrix}\tfrac13\\\tfrac23\end{pmatrix}.
\]
Since the program starts with $\texttt{x}=0$, its expected
output is $v_0=\tfrac13$.
A continuous-state computation thus becomes a finite-state
problem whose expectation can be computed exactly. Our implementation produces a Lean-checkable certificate for the resulting exact value.

In a nutshell, our paper makes the following contributions:
\begin{itemize}[leftmargin=*]
  \item[] \textbf{Type system and inference.}
  We develop a type system and source-to-source
  transformation that identifies and replaces eligible samples by their means, even in higher-order,
  potentially unbounded recursive programs.
  Our inference algorithm finds the greatest assignment of
  determinizable sites permitted by the type system,
  without requiring symbolic marginalization or unrolling
  recursive computations (\cref{sec:language,sec:type-system}).

  \item[] \textbf{Soundness.} We prove that determinization preserves expected values
  and never increases output variance, under suitable
  assumptions. Since the transformation changes the output
  distribution, its correctness requires relating the
  original and transformed executions rather than showing
  distributional equivalence. We develop a relational proof
  based on two interpretations of a common symbolic
  semantics, establishing a stronger tracewise soundness
  result from which the global guarantees follow
  (\cref{sec:soundness,sec:symbolic-semantics}).

    \item[] \textbf{Lean implementation and verification.}
    We implement type inference, determinization, and sampling
  in Lean, and mechanize our soundness theorems.
  Our implementation additionally supports verified
  matrix solving and certificate checking, providing an
  end-to-end correctness guarantee: if the original program
  is domain-safe and its expectation is well-defined, the
  computed expectation is exactly that of the original
  program
  (\cref{sec:implementation}).
  The Lean code is included in the artifact. References to mechanized
  definitions and theorems carry a superscript Lean logo, as in
  \leanmark.

    \item[] \textbf{Evaluation.} We evaluate two applications of determinization.
First, by eliminating continuous sampling, determinization
can reduce infinite-state programs to finite-state programs,
enabling exact computation of their expected values using
existing model-checking techniques.
Second, even when the transformed program remains infinite-state,
reducing its randomness can lower output variance and improve
the precision of Monte Carlo estimates under a fixed
wall-clock budget (\cref{sec:evaluation}).
\end{itemize}
