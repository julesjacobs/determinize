# Determinize: supplementary material

This archive accompanies the submission "Determinize: Type-Directed Variance Reduction for
Probabilistic Programs". It has been anonymized for double-blind review. It contains the Lean
formalization and implementation, the command-line tool, the benchmarks, scripts and recorded
results of the evaluation, the test suites, and a website that shows them in a browser.

| Path | Contents |
| --- | --- |
| `website/index.html` | Start page: the paper's running example and theorems, with links to the parts below |
| `website/sim/index.html` | Simulator: runs a program and its determinization step by step, and compares their output distributions |
| `website/docs/` | API documentation of the Lean development, generated by doc-gen4 |
| `website/source/` | Every text file of the archive outside `website/` as a page with line numbers; the documentation's source links point here |
| `lean/` | Lean 4 project: specification (`Determinize/Spec/`), theorems (`Determinize/Theorems.lean`), proofs (`Determinize/Proof/`), and the implementation behind the command-line tool |
| `tests/`, `examples/` | Test corpus of `.det` programs with expected results |
| `benchmarks/`, `tools/`, `results/` | Benchmarks, the scripts that run them, and the recorded results of the evaluation |
| `run.sh`, `test.sh` | Command-line tool and test entry points |
| `flake.nix` | Optional Nix shell with Lean's installer, Python and Storm |

## Browsing, without installing anything

Open `website/index.html` in a browser. All pages work from disk, without a server and without
building anything: the simulator, the documentation and its cross-references, and the source
pages. What the documentation's scripts add, such as its search box and its lists of instances
and importing modules, needs a server, because browsers do not run those scripts on pages opened
from disk. To use them:

```sh
python3 -m http.server --directory website 8000
# then open http://localhost:8000/docs/Determinize/Theorems.html
```

The documentation of `Determinize.Theorems` (`website/docs/Determinize/Theorems.html`) states
every theorem of the paper; each name in a statement links to its definition, and each
declaration links to its source lines. The pages of the documentation load MathJax from a public
CDN to typeset formulas in docstrings.

## Checking the proofs

Requirements: [elan](https://github.com/leanprover/elan) (Lean's toolchain installer) and Python
3.11 or newer. `lean/lean-toolchain` pins Lean 4.34.1, and `lean/lake-manifest.json` pins
Mathlib.

```sh
cd lean
lake exe cache get    # downloads Mathlib's prebuilt files, several GB
lake build --wfail
```

The library compiles its modules to native code, which its Storm tactic runs while Lean checks
the files. Mathlib's cache does not include that code for Mathlib, so the first build also
compiles the imported part of Mathlib: about half an hour on a 16-core machine. Later builds
reuse it.

`lake build --wfail` fails on any warning, including a `sorry`. It also fails unless every theorem
in `Determinize/Theorems.lean` depends only on the axioms `propext`, `Classical.choice` and
`Quot.sound`, and unless no theorem's statement relies on a declaration from a `Proof` module
other than a proof. On success it prints how many theorems were proved and how many declarations
their statements rely on. `lean/README.md` lists which theorem is which result of the paper and
the definitions that the statements use.

## Running the tool and the tests

From the archive's root, once the Lean project builds:

```sh
./run.sh examples/paper/noisy-product.det
./run.sh --samples 20000 --seed 1 tests/statistical/gaussian.det
./run.sh --result /tmp/model --subject source tests/statistical/discrete.det
./test.sh --all
```

`run.sh` builds and runs the command-line tool; `./run.sh --help` lists its options. `test.sh
--all` runs the test corpus of `tests/` (see `tests/README.md`), the statistical checks and the
checks of the exact certificates.

The comparisons with the Storm model checker need stormpy 1.14.0 (`tools/storm-requirements.txt`).
Point `STORM_PYTHON` at a Python that has it, for example:

```sh
uv venv --python 3.12 /tmp/determinize-storm
uv pip install --python /tmp/determinize-storm/bin/python -r tools/storm-requirements.txt
export STORM_PYTHON=/tmp/determinize-storm/bin/python
./run.sh --storm tests/statistical/discrete.det --prefix /tmp/model --subject source
```

Without `STORM_PYTHON`, `test.sh` reports the Storm comparisons as skipped.

## Evaluation

The recorded results of the paper's evaluation are in `results/`. The scripts that produce them:

- `tools/bench.py` runs the exact (finite-state) and approximate benchmarks of `benchmarks/`;
  its docstring gives the commands (`--exact`, `--approx`, `--det-only`). The recorded runs are
  `results/finite-after-det.json`, `results/infinite-after-det.json` and
  `results/exact-determinization-only.json`.
- `tools/benchmark_approx.py` compares importance sampling and Metropolis-Hastings estimates of
  source and determinized programs with Pyro (`tools/pyro-requirements.txt`); its recorded run
  is `results/approx-results.csv`.
- `benchmarks/exact/scaling/run_scaling.py` measures how determinization scales with program
  size; its results are in `results/scaling/`.
- `tools/benchmark_estimator_variance.py` measures Monte Carlo estimator variance and sampling
  time for RQ3; its individual trials, summary, and plots are in `results/estimator-variance/`.

See `results/README.md` for the commands and the result files used in the current paper.
Timings depend on the machine.

## With Nix

`nix develop .#lean` provides elan, Python and, on Linux, a `STORM_PYTHON` with stormpy. Outside
a git repository, Nix copies the whole directory into its store, `lean/.lake` included once
Mathlib is downloaded; so first make the archive a repository whose files are the archive's:

```sh
git init -q && git add -A
nix develop .#lean
```

## Rebuilding the documentation

`lean/docbuild/` builds the API documentation with doc-gen4. doc-gen4 takes its source links
from a git remote, which the archive does not have; `DOCGEN_SRC=file` makes it link the local
files instead:

```sh
cd lean/docbuild
DOCGEN_SRC=file lake build Determinize:docs
```

The first build also documents Lean and the imported part of Mathlib, which takes hours.
